    Section 4 wrote the boundaries into AGENTS.md; this is what enforces them.\par
    Each rule is backed by a control that holds even if the agent ignores the rule.\par
    Written rules are prompt text: useful, but a confused or manipulated agent can ignore them,
      for instance after a prompt injection: instructions hidden in a web page or file that the
      agent reads and follows as if they came from us.\par
    Controls are enforced outside the model: where the data lives, which credentials exist in
      the session, file permissions, the sandbox mode, network access, approvals, and a
      protected main branch, which accepts changes only through a reviewed pull request.\par
    In Codex the default local mode is workspace-write with the network off; it limits where the
      agent writes and keeps Git metadata read-only, but it still lets the agent write to
      data/raw inside the repository and read files outside it.\par
    So raw data needs its own read-only permissions, and confidential data must not be reachable
      at all.\par
    Which services are approved for which data is a local rule we have to check.}

% ------------------------------------------------------------ verification
\begin{frame}[fragile]{Verifying the running example}
\begin{codefile}[style=py,basicstyle=\ttfamily\fontsize{7.2}{8.75}\selectfont]{tests/data/test\_splitting.py}
def test_one_fold_per_specimen(manifest):                 # fixture: 3 specimens, 2 areas each
    folds = specimen_folds(manifest, n_folds=3, seed=0)   # one fold label per patch
    assert folds.groupby(manifest["specimen_id"]).nunique().eq(1).all()
    assert folds.nunique() == 3                           # each specimen held out once
\end{codefile}
  \vskip1.5mm
  \begin{columns}[T,onlytextwidth]
    \begin{column}{0.66\textwidth}
\begin{terminal}[basicstyle=\ttfamily\fontsize{7}{8.4}\selectfont]{before merging}
$ git diff --stat main...HEAD   # split module, tests, CLI
$ pytest tests/data -q          # all pass
$ python -m sem_seg.data.check_folds \
      folds/specimen-seed0.json # one fold per specimen
$ sha256sum -c checksums/raw-data.sha256   # every file OK
\end{terminal}
    \end{column}
    \begin{column}{0.31\textwidth}
\begin{codefile}[style=sh,basicstyle=\ttfamily\fontsize{7}{8.4}\selectfont]{folds/specimen-seed0.json}
{
  "seed": 0,
  "commit": "...",
  "manifest_sha256": "...",
  "config": {...}
}
\end{codefile}
    \end{column}
  \end{columns}
  \note{\textbf{39:30--40:30}\par
    What verification means for this task.\par
    The key test is small: on a synthetic manifest, every specimen must land in exactly one
      fold, so no held-out fold shares material with training.\par
    Then five checks that a person can run in a few minutes: confirm the scope of the change and
      read the diff itself; run the fast tests; run the fold check on the real manifest; confirm
      that raw data is byte-identical against a committed checksum list kept outside the raw
      folder, with sha256sum from Git Bash; and confirm that the fold file records seed, commit,
      manifest hash and configuration, so the experiment can be reproduced and audited.}
\end{frame}

  \note{\textbf{40:30--41:40}\par
    Three different claims.\par
    The software runs: the command finishes.\par
    It passes the specified tests: no overlap, deterministic, complete.\par
    Neither says whether the evaluation is scientifically meaningful.\par
    That depends on the claim: generalisation to a new specimen, to a new material state or to a
      new microscope are different experiments.\par
    In our HCCI dataset there is one specimen per state, so a specimen split is also a state
      split.\par
    In two of the three folds the held-out state even has phase classes that training never
      shows: austenite and fresh martensite occur only in the as-cast state, retained austenite
      only in the water-cooled one.\par
    An agent cannot be relied on to raise this, and neither can a second AI reviewer checking
      the code.}
